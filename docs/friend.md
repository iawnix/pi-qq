# Friend：可成长的角色陪伴

需要普通 AI 助手、移除关系阶段或后台常驻时，使用 [AI 助手与 systemd 指南](assistant.md)。下文的关系机制仅用于 `character.mode: "companion"`（兼容默认值）。

角色模式在 Pi 的会话持久化之外，增加有来源的经历账本、每人的关系状态和内在感受。它模拟持续的角色发展，不意味着模型具有主观情感，也不保证一定会偏爱某个人。

## 目录与启动

```text
Friend/
├── SOUL.md                      # 自己维护的身份卡，不提交 Git
├── SYSTEM.md                    # 交互规则，不提交 Git
├── qqbot.json                   # QQ 凭据和授权，不提交 Git
├── start-friend.sh
├── .app/pi-qq/                  # 程序仓库、src、dist、node_modules
└── .runtime/                    # 全部忽略于 Git
    ├── pi-agent/                # 专用 Pi 设置、模型与认证
    ├── console-sessions/        # 本地控制台会话
    └── qq/                     # QQ 网关、对话、记忆、经历与关系
```

推荐把程序与角色工作区分开安装：

```bash
mkdir -p ~/Friend/.app
git clone https://github.com/iawnix/pi-qq.git ~/Friend/.app/pi-qq
cd ~/Friend/.app/pi-qq
npm ci
npm run build
cp start-friend.sh ~/Friend/start-friend.sh
chmod +x ~/Friend/start-friend.sh
```

将配置与自己的身份卡放在 `~/Friend`，再配置下方路径。启动脚本优先加载 `.app/pi-qq/src/extension.ts`，工作目录仍是 Friend；源码安装在根目录的旧布局也兼容。更新程序时在 `.app/pi-qq` 内运行 Git/npm 命令，再复制新版启动脚本到 Friend。不要删除 `.app` 或 `.runtime`，前者是程序，后者是模型配置和记忆数据。

保留自己的 `SOUL.md`，将 `examples/friend/SYSTEM.example.md` 复制为 `SYSTEM.md`。QQ 显式读取配置指定的两个文件；它不会自动扫描 AGENTS.md、技能、工作区提示或其他身份卡。文件路径相对于 `qqbot.json` 解析；检查时验证文件存在、非空与大小限制，每轮聊天重新读取。修改身份后可用 `/reset` 开启新对话，避免旧台词影响新设定。

在现有 `qqbot.json` 中合并以下字段，并替换为实际绝对路径：

```json
{
  "agentDir": "/home/your-user/Friend/.runtime/pi-agent",
  "dataDir": "/home/your-user/Friend/.runtime/qq",
  "systemPrompt": "按照角色身份卡、交互规则和程序提供的状态自然交流。",
  "character": {
    "id": "my-friend",
    "soulFile": "SOUL.md",
    "rulesFile": "SYSTEM.md",
    "evolution": true,
    "reflectionIntervalMs": 600000,
    "dailyEventLimit": 3,
    "shareGroupExperiences": true
  },
  "memory": {
    "enabled": true,
    "autoExtract": true,
    "notifyCandidates": false,
    "maxPerScope": 100
  }
}
```

角色模式要求所有已配置群使用 `sessionScope: "member"`。原有 AppSecret、白名单、管理员、图片及工具授权仍然适用。示例不开放本机工具。

默认每个用户在不同场景仍独立。若希望同一个人私聊和群聊连续交流，配置 [identityLinks 完整同步](configuration.md#同一人的私聊与群聊完整同步)。它共享实际 Pi 会话和长期状态，机器人在已绑定群里也可以参考私聊内容；其他群成员不自动加入绑定。下文的“当前身份与场景”在启用绑定时指此人的全部已绑定场景。

希望角色能听群聊、偶尔加入讨论时，可以在该群配置 `replyMode: "smart"`，并在手机 QQ 中允许机器人获取群内全部消息。需要通过 Pi 或明确聊天请求主动发群消息时，再开启 `allowProactive: true` 及 QQ 的群主动发言开关；见[群参与配置](configuration.md#群全量消息与选择性接话)。

用 `./start-friend.sh` 启动，再在 Pi 中 `/model` 选择模型、`/qq start` 连接 QQ。脚本设置独立的 `PI_CODING_AGENT_DIR` 和 `--session-dir`，使用 `--no-extensions --no-skills --no-prompt-templates --no-themes`，只用 `-e` 加载 QQ 扩展。Pi 1.4 的显式扩展路径在关闭自动发现后仍有效。

首次使用需在这个专用 Pi 环境配置模型及认证；已有自定义 provider 可以只迁移所需的 models.json 条目和对应认证，文件权限设为 0600，不复制全局扩展和技能。通过插件注册的 provider 不会自动存在于此环境，需改为独立模型配置或另行明确加载；不要把所有全局插件复制过来。使用普通 `pi` 命令不等同于这个隔离入口。独立 CLI 的 `agentDir` 也需指向同一专用目录。

`character.id` 参与会话、普通记忆和角色数据库的命名空间。更换 ID 会使用另一套角色数据；旧文件仍保留。首次开启角色模式不会自动导入之前的调试对话或事实。所有运行数据必须留在私有目录，并从版本控制中排除。

## 关系与内在感受

角色有五个明确阶段：初识、朋友、要好的朋友、心动、长久相伴。默认阶段为 1，不从历史、模型输出、聊天次数或普通记忆恢复阶段值。

| QQ 命令 | 行为 |
|---|---|
| `/关系` | 查看自己的当前关系阶段 |
| `/关系 下一阶段` | 明确确认，向前一步 |
| `/关系 上一阶段` | 明确确认，退后一步 |
| `/经历 [页码]` | 查看当前身份与场景的经历，每页 8 条 |
| `/经历 删除 编号` | 删除自己的一条经历及其感受贡献 |
| `/重新认识 确认` | 删除当前作用域的普通记忆、经历和对话，阶段回到初识；记忆启停状态不变 |

群内命令仍需满足 @ 规则。群管理员不会因此获得替其他成员调整关系或查看私聊记忆的能力。命令是设置入口，会返回直接的操作结果；普通角色回答不解释机制。

熟悉、信任、舒适和共鸣与明确阶段分开。模型只提出一条有原文引用的经历，每个感受信号只能是 -1、0、1；程序验证格式、引用、限额和去重后保存。阶段字段不在允许的输出中。不存在模型直接写入好感总分的接口。

默认每个作用域至少间隔 10 分钟尝试一次反思，每个 UTC 日最多接受 3 条经历，尝试次数最多为该上限的 4 倍。失败或没有有效经历也占用当次尝试，避免失败重试和无意义互动反复消耗请求。标准化后相同输入和相同经历摘要去重；语义近似但表述不同的内容仍可能重复，可用 `/经历` 管理。

当前初版规则：至少 8 条真实交流经历、分布于至少 3 个 UTC 日期，且信任、舒适、共鸣各达到 5，才标记持续心动倾向。想象场景不贡献这些感受。在同一群中，某成员的最弱感受维度比其他达标成员至少高 2 时，可提供“更期待当前发言者”的内部提示；持平时不强制选出偏爱对象。模型不会获得其他成员的分数表，QQ 命令也不提供排名。

这些阈值是可审查的产品规则，不是心理学量表。表达仍受用户确认的关系阶段限制；不能自动宣告恋爱、要求排他关系或用离线时间惩罚用户。内在感受不因用户暂时不聊天而扣分。删除相关经历会重新计算感受，明确阶段不变。

人物成长目前表现为表达开放程度和分享意愿：来自多个日期的积极交流可以逐渐改变表达，核心身世和人格仍由身份卡确定。不会自动改写 SOUL.md。兴趣和共同话题通过相关经历检索延续，不创建未经证实的新身世。

## 经历、事实与群公共记忆

Pi 会话保存对话与上下文压缩结果；SQLite 经历账本独立于 Pi 压缩摘要。经历不按时间自动淘汰，随互动累积；每次最多检索自己 6 条及当前群公共 6 条，按关键词相关性、时间排序，并提供来源消息和时间。原始对话和数据库大小需由部署者管理，不是无限磁盘存储。

| 数据 | 产生方式 | 作用范围 |
|---|---|---|
| 明确事实、画像 | `/remember`、`记住：内容`、`记住我……`、`/profile` | 当前用户和聊天场景 |
| 事实候选 | 开启 `memory.autoExtract` 后，反思提取带原文依据的自述 | 确认后才能检索，仍受 `maxPerScope` 上限限制 |
| 交流经历 | 反思后的简短事件描述和引用 | 当前用户和聊天场景 |
| 想象经历 | 标为 `imagined` 的角色场景 | 可回忆为想象，不当作真实发生，不增加感受 |
| 群公共经历 | 群交流中被判定适合公开的经历，且开启 `shareGroupExperiences` | 仅当前群 |
| 关系阶段 | 用户明确命令 | 当前用户和聊天场景 |

只对机器人已接受并完成回答的文字请求尝试反思，不后台抓取全群消息。反思只读取本条用户文字和固定身份规则，不读取机器人回复或已检索记忆，避免把回复中的旧记忆再次提取成新经历。它使用无工具、无历史的临时 Pi 会话，会额外调用当前模型；错误仅记状态码，不追加到已经完成的角色回答。角色模式的候选提取与经历反思共用一次请求和反思限额。

`shareGroupExperiences` 默认关闭。开启后，允许模型将本群已有的中性话题交流或想象场景作为公共经历。提示要求个人事实、脆弱处境、秘密和对某成员的感受不得公开；这部分分类由模型完成，不能保证完全正确。私聊与其他群的数据由代码过滤，不能进入当前群公共检索。需要每条公开都由人审核的部署应保持该开关关闭。人物整体开放程度仅使用聚合统计，不传递其他场景的原话、姓名或事件。

明确说“请记住：我喜欢读散文”或“记住我喜欢慢节奏聊天”会直接保存，遵守与 `/remember` 相同的权限和容量限制，不必等候反思；普通“记住了吗？”仍作为聊天。

事实候选不会自动变成用户事实。角色模式不主动在 QQ 中发送候选提示，可在本地 Pi 操作：

```text
/qq memories
/qq memories accept 候选编号
/qq memories reject 候选编号
```

这是本地操作者入口，会显示候选所属作用域；不会向 QQ 发送消息。用户也可继续在自己的 QQ 场景中用 `/memory pending`、`/memory accept`、`/memory reject` 管理。

对相互矛盾的事实，先查看来源，使用 `/memory replace 旧记忆编号 新候选编号` 明确替换。程序原子地确认新候选并移除旧事实，清理旧来源的经历贡献和相关对话；不让模型自行覆盖已确认事实。未经确认的矛盾候选不会被检索。准确与完整仍依赖模型提取和用户管理，原文引用校验不能证明摘要的语义一定正确。

## 删除、隔离和权限边界

`/reset` 只重置对话，保留关系和全部长期记忆。`/forget all` 清除当前作用域的普通记忆和经历，保留明确关系阶段；`/重新认识 确认` 连阶段也重置。删除事实编号也会移除来自同一条消息的经历贡献。

群公共经历可能进入其他成员的持久对话。因此删除经历、替换/删除事实、停用记忆和重新认识时，会清理当前群所有已登记成员的对话历史，保留其他成员的事实、经历和阶段。角色任务全局串行执行，删除会等待前面的回答和反思完成，防止迟到结果重新写入；并发配置在角色模式下实际限制为 1。

存在 `identityLinks` 时，公共经历可能随已绑定成员的上下文进入其他场景，上述清理扩大到本角色全部已登记对话。关系、记忆启停和删除对当前绑定身份的所有场景同步生效。

`/memory off` 停止当前作用域的事实/经历检索与采集，并让其旧经历退出公共检索和感受统计；已有数据保留。明确关系阶段仍有效。重新开启会恢复已有经历的影响。普通事实的 retentionDays 规则不自动删除独立的经历账本，需要删除相关经历或使用 `/forget`。

开启本机工具后，已授权的私聊用户和群成员可以直接用自然语言要求编辑身份卡、规则或项目文件。程序向模型提供配置中的角色文件实际路径；文件每轮重新读取，修改程序或配置则需要重启。无需额外的角色管理开关。关系和记忆数据库仍建议使用管理命令维护；修改身份卡不会自动改变程序记录的关系阶段。

这是应用层的会话与记忆隔离。**完整 read/write/bash 工具以 Pi 的运行账号执行，工作目录不是文件沙箱。** 提示要求不读取其他人的聊天数据，但不能构成操作系统访问边界。需要强隔离时，应关闭聊天中的完整本机工具，或使用独立系统账号/容器及受限管理入口。角色功能不会自动更改现有工具授权，也不会赋予 root 权限。

本地删除不覆盖外部备份、模型服务留存或已发送的 QQ 消息。身份卡、运行目录和真实配置不应推送到公开仓库。
