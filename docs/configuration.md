# 配置与运行

## 配置文件

从 [qqbot.example.json](../qqbot.example.json) 创建配置。CLI 的 `--config` 参数优先于 `PI_QQ_CONFIG` 环境变量；两者均未设置时使用 `~/.pi/qqbot.json`。Pi 扩展读取 `PI_QQ_CONFIG` 或默认位置。

配置采用严格校验，未知字段会报错。显式填写路径时建议使用绝对路径；JSON 中的 `~` 不会展开，相对路径按启动进程的工作目录解析。配置变更后需重启服务。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `appId` | 必填 | QQ 开放平台机器人 AppID |
| `secretEnv` | `QQBOT_APP_SECRET` | 存放 AppSecret 的环境变量名 |
| `model.provider` / `model.id` | 必填 | Pi 模型提供商与模型标识 |
| `allowUsers` | `[]` | 允许私聊的用户 OpenID |
| `groups` | `{}` | 以群 OpenID 为键的群配置 |
| `agentDir` | `~/.pi/agent` | Pi 模型与认证文件目录 |
| `dataDir` | `~/.pi/qqbot` | QQ 会话、记忆与网关状态目录 |
| `systemPrompt` | 内置中文聊天提示 | 聊天系统提示 |
| `historyLimit` | `20` | 每个群会话暂存的非触发文本消息数，范围 0–100 |
| `concurrency` | `4` | 不同聊天同时处理的任务数，范围 1–16 |
| `queuePerChat` | `3` | 每聊天等待任务上限，范围 1–20 |
| `queueTotal` | `64` | 全局等待任务上限，范围 1–500 |
| `timeoutMs` | `180000` | 单次模型任务超时，范围 1000–240000 毫秒 |
| `replyWindowMs` | `240000` | 消息处理与回复的应用时效预算，范围 1000–300000 毫秒 |

AppSecret 只从环境变量读取，不放入配置文件。内置模型或 `models.json` 中定义的模型可用；仅由个人 Pi 扩展注册的模型不会加载。宿主 Pi 需使用 1.4.x；安装本项目不会更新宿主 Pi。

## QQ 权限与身份

使用 QQ 开放平台的机器人账号，需要开通相应 C2C/群消息权限，并满足平台测试成员或发布要求。本项目不支持个人 QQ 账号登录。

| 配置 | QQ 事件字段 |
|---|---|
| `allowUsers` | 私聊 `author.user_openid` |
| `groups` 的键 | 群消息 `group_openid` |
| 群内 `admins` | 该群消息 `author.member_openid` |

OpenID 可从平台调试事件中获取，不是 QQ 号码。私聊 OpenID 和群成员 OpenID 不保证相同。白名单为空时不处理消息；加入群白名单后，该群所有成员均可触发聊天。

每个群支持以下设置：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `requireMention` | `true` | 仅 @ 机器人时响应 |
| `admins` | `[]` | 可重置/停止整个群、管理共享群记忆的成员 OpenID |
| `sessionScope` | `"group"` | `group` 共享上下文；`member` 按群成员隔离 |
| `prompt` | `""` | 追加到系统提示中的群专属说明 |

`requireMention: false` 只改变已接收消息的处理策略，不增加平台权限。平台未推送的群消息不会出现在历史中。要求 @ 的群会暂存最近的非触发文本消息，供下一次提问使用；这部分缓存仅保存在内存中。成员模式下只暂存该成员自己的消息，不会隐式混入其他成员的历史。

### 群会话隔离

旧配置省略 `sessionScope` 时保留共享群行为；示例配置显式选择 `member`。

| 模式 | 对话与长期记忆范围 | 管理权限 |
|---|---|---|
| 私聊 | AppID + 私聊 OpenID | 该用户 |
| `group` | AppID + 群 OpenID | 所有人使用公共记忆，管理员可修改记忆、画像和重置会话 |
| `member` | AppID + 群 OpenID + 成员 OpenID | 每个成员管理自己的会话、画像和记忆 |

隔离的是模型上下文，群内回复仍然公开。不同群、私聊与群聊之间不自动关联身份，也不共享记忆。切换群模式后开启新对话，切换回来也不恢复旧对话；对应作用域原有长期记忆仍然保留。配置中的 `admins` 是机器人管理权限，不会自动同步 QQ 群管理员身份。

成员模式的 `/reset` 只重置自己的会话。管理员可用 `/reset all` 取消并等待全群任务结束，然后为所有成员开启新对话；长期记忆保留。`/stop all` 取消整个群的任务。两种模式都保留按整个群计算的请求上限。

## 画像与长期记忆

记忆独立于 Pi 对话保存在本地 SQLite 中，`/reset` 后仍可检索。当前采用画像优先、关键词匹配和时间排序，不需要向量数据库或额外嵌入模型。

| `memory` 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 允许使用长期记忆；全局关闭时聊天命令不能重新开启 |
| `maxPerScope` | `50` | 每个作用域最多条目数，含画像与候选，范围 1–100 |
| `maxInjected` | `8` | 每次最多注入的已确认条目数，范围 0–20 |
| `maxInjectedChars` | `4000` | 注入条目正文的字符预算，范围 100–8000；不是精确 token 上限 |
| `autoExtract` | `false` | 每次普通文本回答后额外调用聊天模型，提出最多 3 条待确认候选 |
| `retentionDays` | `0` | 新增或更新的已确认记忆保留天数；0 表示不限，最大 3650 |

例如，在 QQ 中发送：

```text
/remember 我偏好 TypeScript 示例
/profile name=小林
/profile language=中文
/profile replyStyle=先给结论，再给示例
/memory
/reset
```

画像字段支持 `name`、`language`、`replyStyle`、`timezone`、`interests`。画像值最多 300 字，普通记忆最多 1000 字；重复设置画像字段会更新原条目并清理旧对话，防止旧值继续参与回答。达到条目上限时需要手动删除，不会自动淘汰其他用户的数据。

自动提取只读取当前用户这一条文字，不读取其他会话。它使用独立、无工具的临时 Pi 会话，会增加模型调用与费用。候选保留 7 天，确认前不会被检索：

```text
/memory pending
/memory accept 候选编号
/memory reject 候选编号
```

共享群仅对管理员发言生成候选；确认后成为群公共记忆。接受候选时开始计算 `retentionDays`，修改配置不会追溯修改旧条目的到期时间。已确认记忆到期后，在该作用域下一次聊天或记忆操作时清理记忆和旧对话；没有后台定时删除任务。

| 操作 | 记忆 | 本作用域对话历史 |
|---|---|---|
| `/reset` | 保留 | 开启新对话，旧文件保留 |
| `/memory off` | 保留，停止检索和新增 | 清理所有代次，开启新对话 |
| `/memory on` | 恢复检索 | 清理所有代次，开启新对话 |
| `/forget 编号` | 删除指定条目 | 清理所有代次与待用群缓存 |
| `/forget all` | 删除全部画像、事实与候选 | 清理所有代次与待用群缓存 |

删除单条记忆也会清理整个作用域的对话，以免已注入旧历史的内容继续生效；其他作用域不受影响。清理范围不包含外部备份、已发到 QQ 的消息或模型服务留存。关闭全局 `memory.enabled` 会停止新记忆的使用，但不会自动抹去之前已经写入对话的内容；需要立即清理时执行 `/memory off` 或 `/forget all`。

## 图片理解与回复

在配置中设置 `images.enabled: true`，并将 `model` 指向支持图片输入的聊天模型，即可直接发送图片或“图片 + 问题”。只发送图片时，默认请模型描述图片。文本模型会明确提示不支持图片，不会自动更换模型。

| `images` 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 开启图片接收、回传和生成入口 |
| `maxBytes` | `5000000` | 单张下载及处理后图片的字节上限，范围 1024–10000000 |
| `timeoutMs` | `10000` | 每张附件下载及处理的超时，范围 1000–30000 毫秒 |
| `maxImages` | `3` | 每条消息附件上限，范围 1–4 |
| `maxPixels` | `16000000` | 解码像素上限，范围 10000–40000000 |
| `maxDimension` | `1600` | 处理后最长边像素，范围 256–4096 |
| `allowedHosts` | `[]` | 可选的下载域名精确白名单；空数组仍只接受公共 HTTPS 地址 |
| `generationModel` | 未设置 | 单独的图片生成模型，包含 `provider` 与 `id` |

只处理平台消息的直接图片附件，不抓取文本中的任意链接或引用消息中的图片。下载拒绝跳转、内网及保留地址，并在实际连接时验证 DNS 结果。接受静态 PNG、JPEG、WebP，解码验证后自动旋转、缩放、去除 EXIF 等元数据，转成 JPEG；透明区域变白，不保留动画或原始图片字节。实际 QQ 附件域名、URL 和媒体权限仍需平台联调确认。

`/image echo` 附带图片可测试回传；这是处理后的图片，不是无损文件转发。生成或编辑图片需要 Pi 中注册为 **image 类型**的模型，视觉聊天模型不能代替它。例如，Pi 1.4 内置的 OpenRouter 图片模型可配置为：

```json
{
  "images": {
    "enabled": true,
    "generationModel": {
      "provider": "openrouter",
      "id": "google/gemini-2.5-flash-image"
    }
  }
}
```

将该片段合并到完整配置，并按 Pi 的方式配置 OpenRouter 认证。模型可用性及编辑能力由服务商决定，`check` 只验证本地模型注册。当前 `models.json` 的自定义聊天模型不等于 image 类型注册。

在 QQ 中发送 `/image 一只在窗边晒太阳的猫` 可生成一张图片；附带图片可请求编辑。生成入口独立于聊天历史，不会自动引用上一张生成图或用户画像；继续编辑时需重新附图。图片下载、生成和发送使用原消息的回复 ID，并遵守队列、群限流和回复时效。取消可阻止尚未开始的发送，但已提交给 QQ SDK 的发送不能撤回。

原始下载缓冲不落盘；用于理解的处理后图片可能随 Pi 会话写入磁盘并发送给模型服务。`/forget` 的历史清理包含这些本地会话图片。

## 队列与限流

同一聊天串行处理，不同聊天按 `concurrency` 并发。排队超限会提示繁忙。取消任务后，队列会等待底层 Pi 请求真正结束再释放会话，避免并发写入。

`rateLimit` 使用固定窗口限制模型请求：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `perUser` | `10` | 每聊天内每用户的请求上限 |
| `perGroup` | `30` | 每群请求上限 |
| `global` | `60` | 全局请求上限 |
| `windowMs` | `60000` | 窗口长度，至少 1000 毫秒 |

超限请求静默丢弃并记录 `rate_limited`。帮助、停止、重置与手动记忆命令不占模型请求限额。图片回传和生成占用请求预算；自动提取是已接受聊天任务的一部分，不单独扣除该预算，但会额外调用模型。

## 数据与回复

聊天内容会发送给配置的模型服务，并以 Pi 会话格式写入 `dataDir/sessions`。不同机器人、私聊用户和群的历史相互隔离；群成员是否共享会话由 `sessionScope` 决定。`/reset` 创建新的会话代次，保留旧文件。普通对话文件没有自动保留期限，需要由部署者管理；记忆到期和 `/forget` 的清理规则如上。

记忆及路由状态位于 `dataDir/memory/<AppID 的 SHA-256>/memory.sqlite`，数据库目录/文件分别按 0700/0600 创建。SQLite 还保存群模式和会话索引，因此关闭长期记忆后仍会创建状态数据库。使用 Node 内置 `node:sqlite`，在 Node 22.19 上可能出现实验性功能提示；已在该版本通过测试。

QQ 会话不加载个人扩展、技能、提示模板、AGENTS.md、SYSTEM.md 或编程工具。引用消息只读取平台提供的文本；直接图片附件按上述图片策略处理。

回复使用原始 `msg_id`，过期或失败时不自动切换为主动消息。默认 240 秒是应用的时效预算，不是 QQ 平台回复期限的保证。长回复最多拆成 3 条，每条最多 4000 个 Unicode 码点；最终限制由平台权限和额度决定。

去重为内存 TTL 去重，无法保证重启后的恰好一次处理。模型答案可能已写入会话，但由于发送失败，QQ 用户尚未收到。原生流式、主动推送和持久收件箱尚未实现。

## 运行与更新

同一 AppID 只运行一个实例。CLI 与 Pi 扩展共享本机实例锁，位于 `~/.pi/qqbot-locks`；跨主机不共享锁。SIGINT、SIGTERM 或退出 Pi 会触发清理；底层请求停止缓慢时，服务退出也会等待。

WebSocket 状态与 Pi 对话历史分别保存。网关最多重连 20 次，耗尽后进入 `failed`；独立 CLI 返回非零退出码，可由进程管理器重启。

更新前停止 QQ 服务并退出 Pi，然后在源码目录执行：

```bash
git pull --ff-only
npm ci
npm run build
```

重新设置环境变量后启动服务。源码目录中的真实配置不会被 Git 跟踪。项目尚未发布到 npm，`package.json` 中的 `private: true` 用于防止意外发布，不影响 GitHub 公开访问或 MIT 授权。

Pi 的间接依赖 Undici 覆盖为 8.12.2，以修复安装时审计发现的问题；此覆盖仅作用于本项目，不会修改宿主 Pi。升级依赖时需重新核对审计结果。

## 故障排查

日志仅记录状态代码，不输出密钥、聊天正文或原始 HTTP 错误体。

| 状态 | 检查项 |
|---|---|
| `gateway_failed` | AppID、密钥、平台权限、网络和重复实例 |
| `request_failed` | Pi 模型认证与模型配置 |
| `queue_full` | 排队数量及模型响应速度 |
| `rate_limited` | 请求频率与 `rateLimit` 配置 |
| `persistence_failed` | 数据目录权限及可用磁盘空间 |
| `memory_extraction_failed` | 候选提取失败或数量达到上限；已发送的聊天回答仍然有效 |
| `invalid_request` | 根据 QQ 中的提示检查命令、图片格式或记忆操作权限 |

先运行 `node dist/cli.js check` 排查本地配置。该检查不验证 QQ 权限或远程模型凭据的有效性。
